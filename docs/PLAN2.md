# План: окно-компаньон и семь инструментов

Семь инструментов работают в отдельном окне, которое можно держать рядом с игрой
или поверх неё, и дублируются в веб-интерфейсе (группа «Инструменты»). Каждый
пункт — отдельный коммит: код → автотесты → проверка в браузере → README →
push. После выполнения пункт отмечается `[x]`.

Общие правила — как в `docs/PLAN.md`: только стандартная библиотека, данные
локальные. Внешние запросы: справочники ao-bin-dumps (по команде
`update-items`) и официальный API киллборда (только если пользователь включил
его в пункте 3.2). Номера событий и смысл параметров сверены по albiondata-client
(MIT) и StatisticsAnalysisTool (GPLv3 — только факты, без кода).

Факты протокола, используемые ниже:

* Join (ответ): 0 — id объекта персонажа, 2 — имя, 8 — зона (любая строка:
  город, `TNL-001`, данж…), 27/28 — фокус, 33 — серебро.
* UpdateFame (82): 1 — вся слава, 2 — слава с множителем зоны без премиума,
  5 — премиум-бонус (+50 %), 10 — слава сумки прозрения, 17 — бонус-фактор.
  Получено = (2 + премиум + 10) × (1 + 17).
* TakeSilver (62): 0 — чей объект (своё, если совпадает с Join[0]), 3 — до
  налогов, 4 — налог кластера, 5 — налог гильдии, 6 — штраф альянса,
  7 — премиум.
* NewLootChest (393): 0 — id, 3 — имя, 21 (23 для `STATIC_…`) — редкость
  0…3; LootChestOpened (395): 0 — id.
* HarvestFinished (61): 0 — чей объект, 4 — предмет, 5/6/7 — количество;
  CraftItemFinished (71): 0 — чей объект; FishingFinished (358).

## Этап 0. Основа

### [x] 0.1 Справочники
* `gamedata.build`: у предметов — слот (`slot`), сила предмета (`ip`, также у
  зачарованных вариантов), двуручность (`2h`), узел Доски судьбы
  (`spec` из `@combatspecachievement`).
* Доска судьбы из `achievements.json`: шаблоны (слава на 100 уровней) и узлы
  (шаблон, категория, множитель славы, родители, предмет-иконка).
* Кластеры из `cluster/world.json`: id → название, тип, переходы (id соседей).
* `download()` скачивает оба файла; версия файла → 2; старый файл читается.
* Тесты на маленьких образцах каждого формата.

### [ ] 0.2 Захват: зона, свой id, новые события
* `AlbionState.zone` — сырая зона из Join[8] / GetGameServerByCluster[0]
  (`uuid@4208` → `4208`), подписка `zone`; рыночная `location` не меняется.
* `AlbionState.object_id` из Join[0].
* Новые события: `new_loot_chest`, `loot_chest_opened`, `harvest_finished`,
  `craft_item_finished`, `fishing_finished` (+ имена в `update-opcodes`).
* Тесты разбора.

### [ ] 0.3 Окно-компаньон
* `albion_trader/window.py`: поиск Edge/Chrome/Chromium, запуск
  `--app=<url>/companion.html` со своим профилем (окно без вкладок и адресной
  строки, помнит размер и место); запасной вариант — обычный браузер.
  «Поверх всех окон» на Windows — WinAPI `SetWindowPos(HWND_TOPMOST)` по
  заголовку окна.
* `static/companion.html` — компактная раскладка: те же модули, только группа
  «Инструменты», переключатель «поверх игры», автообновление.
* `static/js/tools.js` — инструменты регистрируются один раз и работают в обоих
  местах; в основном интерфейсе — группа «Инструменты» и кнопка «Отдельное окно».
* API: `POST /api/window` (`open` / `topmost`), пункт трея «Окно-компаньон»,
  флаг `serve --window`.
* Тесты: построение команды, поиск браузера, API.

## Этап 1. Инструменты

### [ ] 1. Цепочка производства целиком (2.2)
* `chain.py`: дерево «предмет → ресурсы → сырьё» по рецептам; в каждом узле
  цена покупки (рынок, режим) и себестоимость своего производства с возвратом
  ресурсов (бонус города, фокус; для переработки — бонус переработки);
  решение «купить / сделать», итог — минимальная себестоимость и прибыль к
  продаже. Защита от циклов, ограничение глубины.
* Выбор рынка покупки для каждого узла: один рынок или самый дешёвый из
  выбранных; города крафта и переработки — отдельно.
* API `/api/chain`, вкладка с деревом (отступы, пометки «купить/сделать»).
* Тесты: выбор купить/сделать, возврат, цикл, нет цены, фокус.

### [ ] 2. Конструктор билдов со стоимостью (3.1)
* `builds.py`: слоты (оружие, вторая рука, голова, броня, обувь, плащ, сумка,
  ездовое, еда, зелье); у предмета — тир, зачарование, качество.
* Цена по каждому городу (лучшее предложение качества не ниже выбранного),
  сумма по городам, самый дешёвый город по каждому слоту и итог «собрать
  дешевле всего».
* Сила предмета: база + качество (0/20/40/60/100); средняя сила по формуле игры
  (двуручное оружие считается дважды). Мастерство не учитывается.
* Сохранение билдов (`builds`), связь с узлом Доски судьбы.
* API `/api/builds`, `/api/build-price`; вкладка.
* Тесты: цены, качество не ниже, двуручное, средняя сила, сохранение.

### [ ] 3. Мета по киллборду (3.2)
* `killboard.py`: загрузка последних событий официального API
  (`/api/gameinfo/events`, выбор сервера: Америка/Европа/Азия) — выключено по
  умолчанию; включается в интерфейсе. Фоновое обновление с паузой, лимит
  запросов, дедупликация по `EventId`, хранение 7 дней.
* Сводка: популярные билды (оружие + броня + голова + обувь без тира),
  убийства/смерти/доля побед, средняя сила; популярные предметы по слотам;
  «спрос на замену» — что чаще теряют, с текущими ценами.
* Фильтры: период, мин. сила, соло/группа. Кнопка «в конструктор билдов».
* Тесты на образцах ответа API (сеть замокана).

### [ ] 4. Прогресс по Доске судьбы (3.4)
* `destiny.py`: список узлов (поиск), отслеживаемые узлы: текущий уровень и
  слава внутри уровня, цель; остаток славы до цели по таблицам игры.
* Автоучёт: слава нужной категории (бой, сбор, крафт, рыбалка), набранная
  после отметки, прибавляется к активным узлам.
* Прогноз времени по средней славе в час этой категории за выбранный период.
* API `/api/destiny`; вкладка. Тесты.

### [ ] 5. Картограф Дорог Авалона (4.1)
* `avalon.py`: связи между зонами (размер портала 2/7/20, время закрытия,
  заметка); ручное добавление и автоматическое — при переходе через портал
  (сменили зону, одна из зон — Дорога); истёкшие удаляются.
* Маршрут из зоны A в B по активным связям и обычным переходам карты мира
  (Дейкстра по числу переходов), время жизни самого «короткоживущего» портала.
* Подсказки названий зон, текущая зона.
* API `/api/avalon`; вкладка. Тесты.

### [ ] 6. Журнал данжей и сундуков (3)
* Прохождение: вход в зону-данж (тип из карты мира или по имени зоны) до
  выхода в обычную зону; соседние уровни данжа — одно прохождение.
* Сундуки: NewLootChest (имя, редкость) + LootChestOpened → событие `chest`.
* По каждому прохождению: тип, время, слава, серебро, лут (оценка), сундуки
  по редкости; сводка по типам данжей в час.
* API `/api/dungeons`; вкладка. Тесты.

### [ ] 7. Точный учёт славы и серебра (4)
* Слава: полная формула (база, премиум, сумка прозрения, бонус-фактор) и
  источник (бой / сбор / крафт / рыбалка) по событию завершения рядом по
  времени.
* Серебро: только своё (фильтр по id объекта); с мобов чистыми, налоги
  кластера и гильдии; серебро из лута; продажи и покупки на рынке; изменение
  баланса и «прочее» (ремонт, телепорты — разница баланса и учтённого).
* Отчёт за сессию/день/период, в час, график по часам.
* API `/api/economy`; вкладка. Тесты.
