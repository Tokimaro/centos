# План расширения Albion Trader

Документ фиксирует порядок и объём работ. Каждый пункт выполняется отдельным
коммитом; после выполнения пункт отмечается `[x]`.

Общие правила для всех пунктов:

* только стандартная библиотека Python (кроме сборки .exe — PyInstaller в CI);
* данные остаются локальными; единственные исходящие запросы — загрузка
  открытых справочников (ao-bin-dumps, albiondata-client) по явной команде и
  уведомления в Telegram/Discord, если пользователь сам их настроил;
* каждый пункт: код → тесты → проверка в браузере (где есть интерфейс) →
  обновление README → коммит и push;
* ничего, что даёт боевое преимущество (радары, автоклики), не делается.

Источники фактов о протоколе: albiondata-client (MIT, код переносится) и
StatisticsAnalysisTool (GPLv3 — используются только номера событий и смысл
параметров, код не копируется). Коды событий сверены по обоим источникам.

## Этап 0. Основа

### [x] 0.1 Навигация группами и разбиение фронтенда
* Верхний уровень: «Торговля», «Производство», «Мои данные», «Мир», «Оповещения»,
  «Статус»; внутри группы — вкладки второго уровня.
* `static/app.js` делится на `static/js/core.js` (утилиты, API, навигация,
  настройки, экспорт таблиц) и файлы разделов (`trading.js`, `production.js`,
  `personal.js`, `world.js`, `alerts.js`, `status.js`). Сборки нет — обычные
  `<script>` по порядку.
* Готово, когда: все существующие вкладки работают как раньше, адрес вкладки
  запоминается (`#group/tab`), тесты и проверка в браузере проходят.

### [x] 0.2 Игровые справочники (gamedata)
* `update-items` дополнительно скачивает `items.json` (сырой) и `loot.json`,
  `craftingmodifiers.json` из ao-bin-dumps и строит компактный
  `data/gamedata.json`:
  * рецепты крафта (с вариантами зачарования), переработки, количество
    выпускаемых предметов, `itemvalue`, вес, категории магазина;
  * требования улучшения (руны/души/реликвии по шагам);
  * дневники (пустой/полный, базовый объём добычи, таблица лута);
  * семена и животные (урожай, шанс возврата семени, выросшее животное);
  * бонусы городов из craftingmodifiers.
* Модуль `gamedata.py`: загрузка, построение, доступ; без файла разделы
  производства показывают подсказку «выполните update-items».
* Тесты на построение из маленьких фрагментов реальных структур.

### [x] 0.3 Диспетчер событий сборщика и защита от ошибочной маршрутизации
* Разбор событий Photon включается снова (кроме Move — самого частого и
  ненужного), `AlbionState` получает реестр обработчиков операций и событий.
* Из ответа Join запоминается имя персонажа.
* Строковые массивы заказов классифицируются по коду и по содержимому: ответы
  «мои заказы» (коды 92–94, 89 или заказы, где продавец/покупатель — вы) больше
  не попадают в рыночный стакан.
* Тест: ответ «мои заказы» не создаёт рыночных заказов.

### [x] 0.4 Настройки в базе
* Таблица `settings (key, value json)`, API `GET/POST /api/settings`.
* Используется оповещениями, Telegram/Discord, калькуляторами (станции, фокус).

## Этап 1. Торговля без перевозок

### [x] 1. Флиппинг внутри города (идея 2)
* Для каждого (предмет, рынок, качество): лучший заказ на покупку (bid) и
  лучшее предложение (ask).
* Стратегия «заказ → предложение»: затраты `(bid+1)·(1+комиссия)`, выручка
  `(ask−1)·(1−налог−комиссия)`; прибыль, маржа, спред, объём продаж в сутки.
* Отдельно помечается мгновенный арбитраж (ask < bid·(1−налог)).
* API `GET /api/flips`, вкладка «Торговля → Флиппинг» (фильтры: рынки, свежесть,
  мин. маржа/прибыль/объём, тир, чары, поиск).
* Тесты расчёта и API.

### [x] 2. История цен и графики (идея 3)
* Таблица `price_snapshots (item, location, quality, ts, sell_min, sell_amount,
  buy_max, buy_amount)`; снимок пишется после каждого пакета заказов для
  затронутых стаканов, если цена изменилась или прошло ≥10 мин.
* Средняя цена сделок из истории продаж (`history`: серебро/кол-во).
* Хранение 90 дней (очистка в `cleanup`).
* API `GET /api/history?item&location&quality&days`.
* На вкладке «Цены предмета» — график (SVG, без библиотек): мин. продажа,
  макс. покупка, средняя цена сделок; переключатель рынка/качества/периода.
* Тесты записи снимков и API.

### [x] 3. Недооценённые лоты (идея 4)
* Опорная цена = медиана `sell_min` из снимков за 7 дней (≥3 снимка), иначе
  средняя цена сделок за 7 дней.
* Лот недооценён, если скидка ≥ порога; прибыль перепродажи
  `опора·(1−налог−комиссия) − цена`.
* API `GET /api/underpriced`, вкладка «Торговля → Недооценённые».
* Тесты.

### [x] 4. Спрос Чёрного рынка (идея 9)
* По снимкам запросов ЧР и истории продаж ЧР: частота появления запроса,
  средняя/макс. цена, продажи в сутки, давность; сравнение с самой дешёвой
  ценой в городах → потенциальная маржа; рейтинг «цена × объём».
* API `GET /api/bm-demand`, вкладка «Торговля → Спрос ЧР».
* Тесты.

### [x] 5. Список наблюдения и оповещения (идея 5)
* Таблицы `alert_rules` и `alerts`.
* Типы правил: цена ниже / выше (предмет, рынки, качество, сторона), сделка
  (мин. прибыль/маржа, маршрут — параметры поиска сделок), недооценённый лот
  (мин. скидка), «вас перебили» (после п. 11), событие мира (после п. 16).
* Проверка после каждого пакета данных для затронутых предметов; антиспам:
  одно и то же срабатывание не чаще раза в 30 мин.
* Фронтенд: опрос `GET /api/alerts?since=` каждые 10 с, всплывающее окно, звук
  (WebAudio), системное уведомление браузера; вкладка «Оповещения» — правила
  (создание/вкл./выкл./удаление) и история.
* Тесты движка правил и API.

## Этап 2. Производство

### [x] 6. Калькулятор крафта и переработки (идея 1)
* Рецепты из gamedata; ресурсы по ценам выбранного рынка покупки (мгновенно или
  заказом), продукт — на рынке продажи (мгновенно или предложением).
* Возврат ресурсов: `RR = 1 − 1/(1 + бонус)`, бонус = база города (18 %) +
  бонус специализации города из craftingmodifiers + фокус (59 %); возврат не
  применяется к артефактам и прочим невозвращаемым ресурсам.
* Плата станции: `itemvalue·0,1125·ставка/100` (ставка за 100 питания — ввод).
* Итог: себестоимость, выручка, прибыль, маржа, объём продаж; отдельный режим
  переработки (руда+предыдущий тир → слиток и т. п.).
* API `GET /api/craft`, вкладка «Производство → Крафт».
* Тесты формул на эталонных числах.

### [x] 7. Калькулятор зачарования (идея 8)
* Для X.e → X.e+1 (и цепочки до .3): цена базы + N·цена руны/души/реликвии
  против цены готового; качество сохраняется.
* API `GET /api/enchant`, вкладка «Производство → Зачарование». Тесты.

### [x] 8. Дневники работников (идея 11)
* Выгода заполнения: полный − пустой.
* Ожидаемая добыча работника: базовый объём × средняя цена по весам таблицы
  лута × множитель счастья (ввод, по умолчанию 100 %); сравнение «продать
  полный дневник» против «отдать работнику».
* API `GET /api/journals`, вкладка «Производство → Дневники». Тесты.

### [x] 9. Остров и фермерство (идея 12)
* Растения: средний урожай из таблицы лута × цена продукта − стоимость семени ×
  (1 − шанс возврата; с поливом + бонус), за цикл 22 ч.
* Животные: выросшее + шанс потомства × детёныш − детёныш − корм (ввод).
* Модель упрощённая, допущения показаны в интерфейсе.
* API `GET /api/farming`, вкладка «Производство → Остров». Тесты.

## Этап 3. Мои данные

### [x] 10. Учёт сделок и прибыли (идея 6)
* Сборщик: мои открытые предложения/запросы (92/93), завершённые сделки (89),
  почта (174 — список, 176 — чтение: итоги продаж/истечений), мгновенные
  покупки/продажи (83/88, цена берётся из известного заказа).
* Таблицы `my_orders`, `my_trades`, `mails`.
* Журнал сделок, прибыль по предметам (средняя себестоимость), итоги за
  день/неделю.
* API `GET /api/my/orders`, `GET /api/my/trades`, вкладка «Мои данные → Сделки».
* Параметры 83/88 и формат почты уточняются по записи трафика пользователя;
  до подтверждения помечаются как «экспериментально». Тесты на синтетике.

### [x] 11. «Вас перебили» (идея 7)
* Для каждого активного моего заказа — сравнение со свежим стаканом
  (чужие заказы лучше моего) и рекомендуемая цена.
* Колонка статуса в «Мои сделки» + тип правила оповещений «перебили»
  (включено по умолчанию). Тесты.

### [x] 12. Золото и премиум (идея 10)
* Сборщик: ответ 250 (цены и время) → `gold_prices`.
* Вкладка «Мир → Золото»: график, текущая цена; калькулятор премиума:
  стоимость в золоте (ввод) × курс против экономии налога 4 % от оборота в
  месяц → оборот безубыточности. Тесты.

### [x] 13. Сессия: серебро, слава и лут в час (идея 13)
* События: UpdateFame (82), TakeSilver (62), UpdateMoney (81),
  OtherGrabbedLoot (279, только ваш персонаж), Died/KilledPlayer (165/164).
* Сессия начинается при запуске или по кнопке; разбивка по зонам.
* Показатели: слава/ч, серебро/ч, стоимость лута по рынку/ч, список лута.
* Таблицы `sessions`, `session_events`; API `GET /api/session`,
  `POST /api/session/new`; вкладка «Мои данные → Сессия». Тесты.

### [x] 14. Журнал лута группы (идея 14)
* Все события подбора лута (кто, у кого, что, сколько, серебро), зона, время.
* Итоги по игрокам со стоимостью; фильтры; вкладка «Мои данные → Лут». Тесты.

### [ ] 15. Персонаж (идея 15, скорректирована)
* Разбивка славы по деревьям специализаций в протоколе ненадёжна (у
  albiondata-client обработчик отключён), поэтому раздел показывает то, что
  подтверждено: общая слава и её прирост по дням, баланс серебра, очки
  переспециализации, смерти/убийства; данные характеристик (143) сохраняются,
  если придут, и выводятся «как есть».
* Вкладка «Мои данные → Персонаж». Тесты.

### [ ] 16. События мира (идея 16)
* RedZoneWorldMapEvent (480): нападение бандитов (фаза, время окончания),
  FestivitiesUpdate (519): фестивали (начало/конец).
* Таблица `world_events`, вкладка «Мир → События» с таймерами; тип правила
  оповещений «событие мира». Тесты.

## Этап 4. Надёжность и удобство

### [ ] 17. Защита от патчей (идея 19)
* Заказы рынка распознаются и по содержимому (JSON с `AuctionType`), даже если
  коды операций сместились.
* Команда `update-opcodes`: скачивает `operations.go`/`events.go`
  albiondata-client и записывает актуальные номера в `data/opcodes.json`.
* Статус предупреждает: «заказы видны, но коды операций неизвестны — выполните
  update-opcodes». Тесты разбора enum.

### [ ] 18. Экспорт (идея 20)
* Кнопка «CSV» у каждой таблицы: выгрузка видимых строк (разделитель «;»,
  BOM — открывается в Excel). Тест формирования CSV (JS-функция, проверка в
  браузере).

### [ ] 19. Telegram/Discord и доступ из сети (идея 18)
* Настройки: токен бота и chat id Telegram, webhook Discord; оповещения
  пересылаются фоновым потоком с ограничением частоты; кнопка «Проверить».
* `--host 0.0.0.0` разрешён только с паролем (`--password` или настройка):
  HTTP Basic для интерфейса и API. Тесты (отправка — с подменой сети).

### [ ] 20. .exe и значок в трее (идея 17)
* Значок в трее Windows через ctypes (Shell_NotifyIcon): «Открыть», «Выход».
* Автозапуск через реестр (winreg), переключатель в настройках.
* Сборка PyInstaller (`--uac-admin`, один файл) в GitHub Actions на
  windows-latest, артефакт — `AlbionTrader.exe`; локально — `build_exe.bat`.
* Собрать и проверить Windows-части в этом окружении нельзя — они помечаются
  как непроверенные до запуска пользователем.
