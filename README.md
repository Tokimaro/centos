# Albion Trader

Локальное приложение для поиска выгодных сделок в Albion Online: сравнивает цены
в городах и на Чёрном рынке и показывает, где купить и куда отвезти предмет.

Данные собирает **встроенный сборщик**: приложение само читает сетевой трафик
игры, когда вы открываете рынок, так же как это делает albiondata-client проекта
The Albion Online Data Project. Устанавливать и запускать сторонние программы
(albiondata-client, Npcap, Wireshark) не нужно. Всё хранится в локальной базе
`data/market.db`, никуда не отправляется, а веб-интерфейс по умолчанию доступен
только с вашего компьютера (`127.0.0.1`).

```
Albion Online ──UDP 5056──> Albion Trader (встроенный сборщик) ──> SQLite ──> браузер
```

## Возможности

- **Встроенный сборщик**: разбор протокола Photon, определение текущего рынка по
  входу в зону, сбор заказов на продажу и покупку и истории продаж.
- **Быстрая продажа (fast sell)**: сравнение только по ценам мгновенной продажи —
  лучшим заказам на покупку на каждом рынке. Видно, где выгоднее всего сразу сдать
  предмет и насколько это лучше вашего рынка.

- **Город → город** и **город → Чёрный рынок**: Тетфорд, Лимхерст, Бриджвотч,
  Мартлок, Форт Стерлинг, Карлеон, Брецилиэн, логова контрабандистов. Рынки
  порталов (например, Портал Лимхерста) — это рынки своих городов, данные объединяются.
- Налоги: 4% с премиумом / 8% без, 2,5% за размещение заказа.
- Режимы покупки: выкуп предложений или свой заказ на покупку. Режимы продажи:
  мгновенно в запросы или своим предложением (на Чёрном рынке только мгновенно).
- Учёт качества: запрос на качество *q* можно закрыть предметом качества *q* и выше
  (например, купить «Выдающееся» дешевле «Хорошего» и сдать на ЧР).
- Проход по стаканам: считается реальное количество, итоговая прибыль и вложения,
  а не только разница верхних цен.
- Фильтры: города, свежесть данных, мин. прибыль/маржа, тир, зачарование, поиск по
  названию (русские и английские названия).
- Страница цен предмета по всем рынкам и качествам, средний объём продаж в сутки
  (если в игре открывали график истории цен).
- Устаревшие данные: заказы с истёкшим сроком удаляются, а заказы, которые пропали
  из более свежего снимка стакана, считаются выкупленными.

## Установка и запуск

### Вариант 1: AlbionTrader.exe (Windows, без Python)

Готовый `AlbionTrader.exe` собирается автоматически в GitHub Actions (вкладка
Actions → последний запуск «tests-and-exe» → артефакт `AlbionTrader-exe`) или
локально скриптом `build_exe.bat`. Запуск: двойной щелчок — Windows спросит права
администратора (нужны для чтения трафика игры), откроется браузер, в трее
появится золотой значок. При первом запуске справочники скачаются сами; данные
хранятся в `%LOCALAPPDATA%\AlbionTrader\data`, лог — там же
(`albion_trader.log`, до 5 МБ × 3 файла с ротацией; ошибки самого запуска — в
`launcher.log`). Повторный запуск, пока программа уже работает, просто открывает
браузер, а не второй экземпляр. Аргументы командной строки можно добавлять к
стандартным (`AlbionTrader.exe --port 8585`), папка данных подставится сама.

Если ваша учётная запись Windows — не администратор и в окне UAC вы вводите
пароль *другой* (администраторской) учётной записи, программа запустится от её
имени и `%LOCALAPPDATA%` будет указывать в её профиль. Чтобы данные лежали в
одном месте, задайте переменную окружения `ALBION_TRADER_DATA` (например,
`C:\AlbionTrader\data`) — она важнее папки по умолчанию.

Значок в трее: двойной щелчок открывает интерфейс, правая кнопка — меню
«Открыть», «Запускать вместе с Windows», «Выход». Оповещения дублируются
всплывающими уведомлениями Windows, даже когда браузер закрыт. Автозапуск
делается задачей Планировщика с наивысшими правами (так программа с правами
администратора стартует при входе без запроса UAC); включается в меню значка
или во вкладке «Статус». Задача запускает `AlbionTrader.exe --autostart` — в этом
режиме браузер не открывается, программа тихо сидит в трее.

### Вариант 2: из исходников (Python)

Нужен Python 3.10+ (сторонние библиотеки не нужны).

**Windows** — запустите `start.bat`. Он сам находит Python через лаунчер `py`
(команда `python` в Windows часто ведёт в Microsoft Store и не работает). Он запросит права администратора (без них
Windows не даёт читать сетевой трафик), при первом запуске скачает названия
предметов и откроет http://127.0.0.1:8484. Если брандмауэр Windows спросит про
Python — разрешите доступ, иначе входящие пакеты игры не будут видны.

**Linux** — `./start.sh` (запускает через `sudo`), либо выдайте Python право
захвата один раз и запускайте без root:

```sh
sudo setcap cap_net_raw+ep "$(readlink -f "$(command -v python3)")"
python3 -m albion_trader serve
```

Вручную:

```sh
py -m albion_trader update-items       # Windows; в Linux — python3. Один раз: названия предметов (RU/EN)
py -m albion_trader serve              # от администратора / root
```

`update-items` только скачивает открытые справочники из
[ao-data/ao-bin-dumps](https://github.com/ao-data/ao-bin-dumps): названия
предметов (`data/items.json`) и рецепты, зачарование, дневники, фермерство и
бонусы городов (`data/gamedata.json`, нужны калькуляторам производства). Ваши
данные при этом никуда не отправляются. Без справочников вместо названий будут
ID, а разделы производства попросят выполнить команду. После крупных патчей
игры команду стоит запускать снова.

macOS встроенным сборщиком не поддерживается — там можно использовать внешний
albiondata-client (см. ниже).

## Сбор данных

1. Запустите Albion Trader, затем игру (или наоборот — неважно).
2. **Смените зону** (выйдите из города и зайдите обратно или войдите в игру заново):
   так сборщик узнаёт, на каком рынке вы находитесь. Текущая локация видна в
   правом верхнем углу и во вкладке **Статус**.
3. Открывайте рынки нужных городов и Чёрного рынка (в Карлеоне): вкладки
   «Купить» (предложения) и «Продать» (заказы на покупку). Каждая просмотренная
   страница сохраняется.
4. Для объёмов продаж открывайте у предметов график истории цен.

В Карлеоне обычный рынок находится в отдельной зоне «Caerleon Market» (3005), а
Чёрный рынок — в самом городе (3003); переходы между ними сборщик видит сам.

Если на ПК есть виртуальные сетевые адаптеры (WSL, Docker, Hyper-V, VPN), система
может показывать каждый пакет игры дважды — сборщик сам отбрасывает такие дубли.

Страницы рынка, открытые до того, как сборщик узнал локацию, не сохраняются: если
запустили приложение, уже стоя на рынке, выйдите из здания рынка и зайдите снова.

Если в **Статусе** растёт счётчик «ответов рынка не дошло целиком», теряются
сетевые пакеты (чаще всего в людных зонах вроде Карлеона) — просто обновите
страницу рынка ещё раз. Если не помогает, запишите трафик для диагностики:
`start.bat --record data\capture.pcap` (файл содержит и ваш ник/чат — не
выкладывайте его публично).

Если игра начнёт отдавать данные рынка в зашифрованном виде, приложение покажет
это в статусе — в таком случае цены не может собрать ни один сборщик.

После крупных обновлений игры могут измениться номера операций протокола. Заказы
рынка всё равно распознаются по содержимому, а «Статус» предупредит, что коды
устарели. Актуальные номера подтягиваются из albiondata-client кнопкой «Обновить
коды операций» во вкладке «Статус» или командой
`python -m albion_trader update-opcodes` (пишет `data/opcodes.json`). Файл можно
править и вручную (значения по умолчанию — в `albion_trader/capture/albion.py`):

```json
{"auction_get_offers": 81, "auction_get_requests": 82, "join": 2}
```

Для отладки можно разобрать запись трафика из Wireshark (формат .pcap):
`python -m albion_trader replay capture.pcap`.

### Внешний albiondata-client (необязательно)

Приём данных по HTTP остался: если встроенный сборщик у вас не работает, можно
запустить `python -m albion_trader serve --no-capture` и albiondata-client с
параметром `-i http://127.0.0.1:8484` — он заменяет публичный сервер, так что
данные всё равно уходят только в ваше приложение. Чтобы в базу не могли писать
другие программы на ПК, добавьте `--token auto` (адрес для клиента покажется в
логе и во вкладке **Статус**).

## Как пользоваться

- **Сделки** — выберите, где покупать и где продавать, режимы и фильтры.
  Столбцы: цена покупки и продажи, прибыль за штуку (после налогов и комиссий),
  маржа, количество, которое можно провести с прибылью, итоговая прибыль,
  вложения, объём продаж в сутки и возраст самой старой из цен. Цифра в скобках
  в столбце «Кач.» — качество, которое нужно купить, если оно отличается.
  Клик по названию открывает сравнение цен предмета.
  Кнопка **«Только fast sell цены»** сравнивает рынки только по ценам быстрой
  продажи: покупка — своим заказом по цене лучшего заказа на покупку в городе А,
  продажа — мгновенно в заказы на покупку в городе Б.
- **Быстрая продажа** — таблица «предмет × рынок» с лучшими заказами на покупку.
  Выберите «Мой рынок», чтобы видеть, сколько серебра на руки вы выиграете, отвезя
  предмет на лучший рынок; без него показывается разница между лучшим и худшим
  рынком. Предмет качества Q можно сдать в заказ качества Q и ниже — это учтено.
- **Цены предмета** — лучшие цены на каждом рынке по качествам и график за
  сутки/неделю/месяц/3 месяца: минимальная цена продажи, максимальная цена
  покупки (снимки копятся при каждом просмотре рынка, хранятся 90 дней) и
  средняя цена сделок (когда вы открываете в игре график цен предмета).
- **Флиппинг** — перепродажа внутри одного города: свой заказ на покупку на 1
  серебро выше лучшего, затем своё предложение на 1 серебро ниже лучшего. Учтены
  налог и обе комиссии; «Потенциал/сут» = прибыль × продажи в сутки. Значок в
  столбце «Мгновенно» — предложение дешевле заказа на покупку даже после налога.
- **Недооценённые** — предложения заметно дешевле обычной цены (медиана
  минимальных цен за 7 дней по снимкам или средняя цена сделок) и прибыль, если
  купить и перевыставить. Чтобы опорная цена появилась, рынок нужно посмотреть
  хотя бы 3 раза с интервалом.
- **Спрос ЧР** — что Чёрный рынок покупает чаще и дороже за сутки/неделю/месяц:
  в скольких днях был заказ, средняя и максимальная цена, продажи в сутки, самое
  дешёвое предложение в городах и маржа. Данные копятся с каждым просмотром ЧР.
- **Производство → Крафт и переработка** — прибыль по всем рецептам сразу:
  ресурсы по ценам рынка покупки (мгновенно или заказом), продукт на рынке
  продажи. Учтены возврат ресурсов (18 % королевского города + специализация
  города + 59 % за фокус; артефакты не возвращаются), плата станции (ставка за
  100 питания), налог и комиссии. Отдельные режимы переработки и трансмутации.
- **Производство → Зачарование** — предмет .a + руны/души/реликвии (для еды и
  зелий — соусы и экстракты) против продажи готового .b; «экономия» —
  насколько дешевле зачаровать самому, чем купить готовый.
- **Производство → Дневники** — выгода заполнения (полный − пустой) и
  ожидаемая добыча работника по таблице добычи с учётом счастья; что выгоднее —
  продать полный дневник или отдать работнику.
- **Производство → Остров** — упрощённая доходность растений (за цикл и в
  сутки: урожай по таблице, возврат семени, полив) и животных (выросшее +
  потомство − детёныш − корм). Допущения описаны на вкладке.
- **Мои данные → Сделки** — ваши открытые заказы, журнал покупок и продаж,
  прибыль по предметам (по средней цене покупок) и по дням. Собирается само,
  когда вы открываете в игре вкладку своих заказов, завершённые сделки и почту
  с итогами заказов; мгновенные покупки/продажи записываются в момент сделки.
  Часть форматов подтверждена только исходниками открытых инструментов — такие
  записи помечены «β». У каждого открытого заказа — статус «лучший» или
  «перебит» с рекомендуемой ценой; правило «Мой заказ перебили» включено по
  умолчанию и срабатывает при просмотре рынка с более выгодным чужим заказом.
- **Мои данные → Сессия** — слава, серебро и лут в час за игровую сессию
  (начинается при запуске приложения или по кнопке), изменение баланса,
  убийства/смерти, лут со стоимостью по рынку и разбивка по зонам.
- **Мои данные → Лут и бои** — кто что подобрал рядом с вами (за сессию,
  сутки, неделю, месяц), итоги по игрокам со стоимостью по рынку; журнал
  убийств и смертей рядом с вами (с гильдиями), ваши убийства/смерти, их
  соотношение и кто убивал вас чаще всего. Поиск по имени работает везде.
- **Мои данные → Зоны** — где выгоднее фармить: для каждой зоны за период
  время, визиты, слава и доход в час (серебро с мобов + поднятое серебро +
  лут по рынку), смерти. Паузы больше 10 минут считаются отходом от игры.
- **Мои данные → Персонаж** — общая слава и прирост по дням, баланс серебра
  (графики), очки переспециализации, убийства и смерти. Разбивку славы по
  веткам специализаций протокол надёжно не отдаёт.
- **Мир → События** — нападение бандитов (фаза и обратный отсчёт) и фестивали
  (идут / скоро начнутся). Приходят, когда вы открываете карту мира; правило
  оповещений «События мира» включено по умолчанию.
- **Мир → Золото и премиум** — курс золота (собирается, когда вы открываете
  биржу золота в игре) и калькулятор: окупается ли премиум при ваших продажах
  (экономия 4 % налога против стоимости премиума по текущему курсу).
- **Мир → Радар** — карта вокруг персонажа: игроки (гильдия, здоровье), мобы
  (зачарование), ресурсы (вид, тир, зачарование, запас), сундуки, серебро и
  прочие объекты `New…`/`…Object`. Строится по событиям `New…`, `Move`,
  `Leave`, `HarvestableChangeState`; своя позиция — из входа в зону (Join) и
  своих шагов, смена зоны очищает карту. Слои, масштаб, поворот на 45° как у
  камеры игры, минимальный тир ресурсов, список ближайших. События движения —
  самые частые, поэтому сборщик разбирает их, только пока вкладка открыта.
  Номера событий обновляются вместе с рыночными (`update-opcodes`) и
  переопределяются в `data/opcodes.json` (`{"events": {"new_mob": 126}}`);
  ключи параметров — в `data/radar.json`
  (`{"params": {"new_mob": {"position": [8]}}}`). Таблица «Коды событий» внизу
  вкладки показывает все пришедшие события с параметрами и отмечает
  координаты (`·pos`) — по ней видно, под каким кодом приходят объекты на
  вашем сервере.

  **Фон карты** — схема текущей зоны в цветах карты зоны из игры: бирюзовая
  вода, охристая суша (светлее на возвышенностях), оранжевые дороги и настилы,
  тёмные мостки, светлые участки под дома, серые постройки, края скал; выходы
  с названиями соседних зон, банк и рынок. В статичном виде зона обведена
  рамкой со сторонами света на углах ромба, как в игре. Строится
  из раскладки уровня игры в открытом репозитории ao-bin-dumps
  (`cluster/*.cluster.xml` → `templates/*.template.xml`, те же координаты, что
  приходят в событиях) и скачивается при первом входе в зону, пока радар открыт;
  дальше берётся из `data/zonemaps`. Заранее скачать схемы городов и всех зон, где
  вы бывали: `python -m albion_trader update-maps` (или перечислите id зон,
  `--all` — все зоны игры, это сотни мегабайт). Для случайных данжей и Туманов
  раскладки нет — там радар без фона.

  **Вид карты**: «за персонажем» — вы в центре, карта едет под вами (масштаб
  настраивается); «статичная карта зоны» — вся зона неподвижна и целиком на
  экране (можно приблизить), двигаются точки, включая вас (белая метка с
  кольцом). При мелком масштабе подписи сокращаются до имён игроков.

  **Ресурсы**: показывать значком, надписью или и тем и другим. Свои значки
  работают без интернета и нарисованы как узлы на карте игры: руда — валун с
  кристаллами цвета тира, камень — груда глыб, дерево, куст волокна, шкура;
  ореол — зачарование, камешек в углу — тир, рядом — «тир.зачарование».
  Вариант «из игры» берёт картинки предметов с render.albiononline.com
  (официальный сервер картинок; это внешний запрос из браузера, поэтому он
  выключен по умолчанию).

  **Игроки** (как в ZQRadar) на карте показаны компактно: точка цвета
  статуса, ♞ — на маунте, полоска HP — только у раненых, подпись — имя (или
  имя и гильдия, или без подписи). Наведите курсор на игрока — подсказка с
  гильдией и альянсом, статусом, HP, маунтом и снаряжением; то же — в таблице
  «Игроки рядом» под картой. Статус: «враждебный» — PvP-флаг
  (NewCharacter[53] = 255), а в красных и чёрных зонах — все, кроме своих;
  «фракция» — флаг города (1–6, цвет точки — цвет города); «мирный»; «свой» —
  ваша гильдия или альянс (укажите их в настройках). Враждебных, фракционных
  и мирных можно скрывать по отдельности. HP — из NewCharacter[22/23],
  HealthUpdate[3] и RegenerationHealthChanged[2/3]; маунт — Mounted[11] (или
  [10] = −1); снаряжение — NewCharacter[40] и CharacterEquipmentChanged[2]
  (оружие, вторая рука, голова, броня, обувь, сумка, плащ, маунт, зелье, еда;
  названия — из справочника предметов); флаг — ChangeFlaggingFinished[1].
  Под картой — таблица «Игроки рядом» со всеми этими сведениями. Номера
  событий Mounted и ChangeFlaggingFinished после патчей сдвигаются —
  обновите их `update-opcodes` или проверьте по таблице «Коды событий».

  **Ещё на радаре:**
  - *Оповещение о враждебных* — звук и вспышка рамки, когда враждебный игрок ближе
    заданного радиуса; по желанию — оповещение программы (правило «Радар:
    враждебный игрок» → Windows, Telegram, Discord), не чаще раза в 5 минут на игрока.
  - *Стрелки* на краю карты к враждебным игрокам, сундукам, боссам и ценным узлам за
    её пределами (несколько в одном направлении — одна стрелка «×N»).
  - *Отряды* — 4+ враждебных игрока рядом обведены с подписью «отряд: N»;
    *следы* — путь игроков и мобов за последние 8 секунд.
  - *Сила и роль* игрока — средняя сила предметов снаряжения (из справочника, без
    учёта качества) и роль по оружию (хил, танк, поддержка, урон); при включённом
    киллборде — убийства и смерти. *История встреч* — кто, сколько раз, был ли
    враждебен, в каких зонах.
  - *Друзья* и *скрываемые* игроки — списками имён.
  - *Матрица ресурсов* «вид × тир», минимальное зачарование; *цена узла* по
    собранным ценам рынка (подпись значка — «цена узла»), минимальная цена;
    *маршрут сбора* через ближайшие ценные узлы.
  - *Истощённые узлы* — бледный значок с таймером до ожидаемого респауна (время
    задаётся); *тепловая карта* — где в зоне встречались ресурсы (копится в базе).
  - *Мобы* — названия, тир и категория из mobs.json (ao-bin-dumps; номер моба в
    событии + сдвиг из настроек = строка файла; правильность сдвига видно в
    подсказке), фильтр по тиру, «только боссы», живые ресурсы значком ресурса.
  - *Сундуки* — цвет по редкости, открытые — серые.
  - *Свои картинки карт* — `data/maps/<id зоны>.png` (как карта зоны в игре, ромбом;
    `<id>.json` с `{"kind": "flat"}` — вид сверху, `"bounds"` — свои границы).
  - *Профили* «Фарм», «PvP», «Сбор» и свои; *клавиши* на карте и в окне: +/−
    масштаб, M вид, L подписи, B фон, R поворот, H тепловая карта, T следы, 1–5
    слои, P профиль.
  - *Перемотка записи* — .pcap из папки data (например, `serve --record
    data/radar.pcap`) проигрывается на радаре с паузой, скоростью и ползунком;
    рыночные данные и история встреч из записи не сохраняются.
  - *Автоисправление номеров событий* — радар узнаёт Move, NewCharacter, NewMob,
    NewHarvestableObject и список ресурсов по форме параметров и предлагает
    правильные номера (кнопка «Применить» или автоматически); номера пишутся в
    `data/opcodes.json`.
  - *Бледные объекты* — игроки и мобы без событий дольше 20 секунд.
  - *Оверлей* (Windows, экспериментально) — окно радара полупрозрачное и
    пропускает клики в игру; включается и выключается на вкладке.

  **Окно радара** — кнопка «Открыть окно радара» на вкладке: отдельное окно
  только с картой и значками, без панелей (удобно держать поверх игры — флажок
  «Поверх игры» рядом, в Windows). Все настройки (слои, масштаб, поворот,
  фон и его яркость, подписи) меняются на вкладке и сразу применяются в окне.
- **Оповещения** — правила «цена ниже/выше», «сделка между рынками»,
  «недооценённый лот» (а также «мой заказ перебили» и «событие мира» — см. ниже).
  Проверяются при каждом просмотре рынка в игре; сработавшее правило показывает
  всплывающее окно, звук и системное уведомление браузера (кнопка «Разрешить
  системные уведомления»). Одно и то же срабатывание — не чаще раза в 30 минут.
  На странице предмета есть кнопка «Оповестить о цене».
  В разделе «Отправлять оповещения в Telegram или Discord» можно указать своего
  бота (токен от @BotFather и chat id) или вебхук канала Discord, выбрать типы
  оповещений и нажать «Проверить».
- **Статус** — состояние сборщика, текущая локация, что и когда собрано.

Над каждой таблицей есть кнопка **CSV** — выгрузка видимых строк для Excel
(разделитель «;», десятичная запятая).

Чем свежее данные, тем точнее сделки: цены на Чёрном рынке меняются быстро,
поэтому перед поездкой обновите рынки в игре. Приложение не учитывает вес груза и
риск перевозки через красные/чёрные зоны.

## Инструменты и окно-компаньон

Группа **«Инструменты»** есть и в основном интерфейсе, и в отдельном
**окне-компаньоне** — компактном окне без вкладок и адресной строки, которое
удобно держать рядом с игрой. Открыть окно: кнопка **«⧉ Отдельное окно»** в шапке,
пункт **«Окно-компаньон»** в меню значка в трее или флаг `serve --window`.
Окно открывается через Edge/Chrome в режиме приложения со своим профилем (помнит
размер и место); галочка **«Поверх игры»** закрепляет его поверх остальных окон
(Windows; игра должна быть в оконном режиме или «окно без рамки»). Если Edge и
Chrome не найдены, страница откроется в обычном браузере. С другого устройства
кнопка открывает всплывающее окно браузера. Вкладки инструментов обновляются
сами каждые 20 секунд.

- **Сейчас** — текущая зона, персонаж и итоги сессии: слава, серебро и лут в час.
- **Цепочка** — производство предмета целиком: «предмет → ресурсы → сырьё».
  Для каждого узла сравниваются «купить» (самый дешёвый из выбранных рынков) и
  «сделать самому» (крафт или переработка с возвратом ресурсов по бонусу города
  и фокусу) и выбирается дешевле. Итог — себестоимость, прибыль при продаже,
  нужный фокус и список «что и где купить». Строки дерева раскрываются.
- **Билд** — конструктор комплекта: оружие, вторая рука, голова, броня, обувь,
  плащ, сумка, ездовое, еда и зелья (с количеством), для каждого — качество.
  Показывает цену целиком в каждом городе (и чего где не хватает), самый
  дешёвый город по каждому слоту, итог «собрать дешевле всего» и среднюю силу
  предметов по шести слотам (двуручное оружие считается и за вторую руку;
  мастерство персонажа не учитывается). Предложения берутся качества не ниже
  выбранного. Билды сохраняются; у оружия виден узел Доски судьбы.
- **Мета** — популярные билды по свежим убийствам официального киллборда игры:
  сколько боёв, доля побед, средняя сила (без тиров и зачарования, фильтры по
  периоду, силе, соло/группа). Кнопка «⇢ билд» открывает билд в конструкторе с
  ценами. Ниже — популярные предметы по слотам и «спрос на замену»: что чаще
  теряют, с текущей ценой и оборотом. **Загрузка выключена по умолчанию** —
  включите галочку и выберите сервер (Европа/Америка/Азия); тогда приложение раз
  в 5 минут запрашивает `gameinfo*.albiononline.com` (это единственный запрос к
  серверам игры) и хранит события 7 дней.
- **Доска** — прогресс по Доске судьбы. Найдите узел (оружие, броня, ремесло,
  сбор, рыбалка…), укажите текущий уровень, славу внутри уровня (видна в игре на
  доске) и цель — таблица славы берётся из данных игры с множителем узла.
  Слава нужного типа, набранная после отметки, прибавляется сама: источник
  определяется по событиям игры (сбор, крафт, улов рядом по времени — иначе бой).
  Прогноз — время игры до цели по средней славе в час за 1/7/30 дней. Из
  конструктора билдов ссылка на узел оружия открывает его здесь.
- **Авалон** — картограф Дорог Авалона. Переход через портал (смена зоны, где
  одна из зон — Дорога) запоминается сам; время жизни портала в трафике не
  видно — укажите его кнопкой «время» (без времени автосвязь живёт сутки).
  Связи можно добавить вручную: зоны A и B (с подсказками названий), размер
  портала (2/7/20), сколько осталось. «Маршрут» ищет кратчайший путь по числу
  переходов через активные порталы и обычные переходы карты мира и показывает,
  когда закроется ближайший портал на пути. Истёкшие связи удаляются.
- **Данжи** — журнал прохождений: от входа в данж до выхода в обычную зону
  (уровни одного данжа — одно прохождение; тип — статичный, коррапт, хеллгейт,
  экспедиция, туманы или случайный данж). По каждому — время, слава и доход в
  час (серебро с мобов, серебро и предметы из вашего лута по рыночной оценке),
  открытые сундуки по редкости и смерти; сверху — сводка по типам данжей.
  Учитывается только своё серебро (игра присылает его и за участников группы).
- **Учёт** — точный учёт славы и серебра за сессию, сегодня, 7 или 30 дней.
  Слава — по полной формуле игры (база с множителем зоны, премиум, сумка
  прозрения, бонусы) и по источникам: бой, сбор, крафт, рыбалка. Серебро —
  только ваше: с мобов до и после налогов (налог кластера, гильдии, штраф
  альянса), из лута, продажи и покупки на рынке, изменение баланса и «прочее» —
  то, что баланс изменился сильнее учтённого (ремонт, телепорты, комиссии).
  Графики по часам (для длинных периодов — по дням) и таблица по дням.

## Проверка радара на своём компьютере (Windows)

Запустите Albion Trader (лучше — и игру, и зайдите в зону), затем **`check_radar.bat`**
(из собранной программы: `AlbionTrader.exe check-radar --window`). Он:

1. прогоняет автотесты (если программа из исходников — папка `tests` рядом);
2. проверяет окружение: права администратора, открытие сокетов захвата, Python;
3. проверяет окно радара: найден ли Edge/Chrome, есть ли функции Windows для
   «поверх игры» и оверлея; **откроет окно радара на несколько секунд**, включит
   «поверх игры» и оверлей и выключит их обратно;
4. проверяет сеть (ao-bin-dumps для схем зон и мобов, render.albiononline.com для
   значков — необязательно) и файлы радара в `data` (схемы, мобы, номера событий);
5. проверяет работающую программу: приходят ли события от игры, известна ли зона,
   готов ли фон, нет ли признаков, что номера событий на сервере другие;
6. открывает в браузере **страницу самотеста радара** (`/radar-selftest.html`):
   тесты логики (статусы игроков, фильтры, маршрут, отряды, геометрия карты),
   отрисовка на canvas и ответы программы. Кнопка «Скопировать результат» — чтобы
   прислать его.

Отчёт — `data/radar_check.txt` (имён игроков в нём нет). `[FAIL]` — ошибка,
`[WARN]` — предупреждение (например, игра не запущена или нет интернета).

Автотесты для разработки: `python -m unittest discover -s tests` — Python-тесты
сервера, разбора событий, схем зон, перемотки, окна (вызовы Windows проверяются
через подмену), а также JS-тесты интерфейса радара через Node.js, если он
установлен (`tests/js/run_radar_js.js`; без Node они пропускаются, а в браузере
всегда доступны на странице самотеста).

## Бот для своего сервера (Windows)

Вкладка **«Боты»**: бот управляет окном игры на этом компьютере (тем, что активно при
запуске) и видит мир через его трафик — позицию, зону, ресурсы, мобов, добычу, здоровье.
Работает **один бот за раз**. **Только для своего сервера** — на официальных серверах
Albion Online за ботов банят. Пока вы двигаете мышью или печатаете, бот ждёт; клавиша
остановки (по умолчанию **F12**) останавливает его.

**Подготовка (один раз):**

1. Запустите Albion Trader **от администратора**, включите бота во вкладке «Боты» и
   **смените зону** в игре — так бот узнаёт персонажа.
2. **Калибровка** на открытом месте (в 7 м нет ресурсов): 4 клика рядом с персонажем —
   бот вычисляет, как экран переходит в координаты мира и где на экране персонаж.
3. **Места**: встаньте у банка, у торговца рынка и т. п. и нажмите «Запомнить место».
4. **Точки интерфейса** (для рынка и добычи): «Указать» → клик по кнопке или полю в окне
   игры — торговец, вкладки «Продать»/«Купить», поиск, первый предмет, «Заказ на
   продажу/покупку», цена, количество, подтверждение, «Взять всё».

**Задачи:**

- **Сбор ресурсов** — виды, тиры, зачарование, радиус от старта; к узлу идёт, не кликая
  в чужие узлы, собирает до истощения, без ресурсов гуляет, от враждебных игроков отходит.
- **Рынок** — бот идёт к выбранному месту (даже из другой зоны), для каждого заказа берёт
  предмет из списка, цену — из собранных данных этого рынка (на «шаг» дешевле лучшей
  продажи или дороже лучшей покупки) и проходит по точкам: торговец → вкладка → поиск →
  название → первый предмет → «Заказ» → цена → количество → подтверждение → Esc,
  проверяя, что игра отправила запрос серверу. Свой порядок действий — свой макрос.
- **Перевозка между городами** — место погрузки (город А) с макросом погрузки (например,
  забрать из банка) → маунт → маршрут по зонам допустимой опасности (только синие,
  с жёлтыми, с красными, любые) → место разгрузки (город Б): макрос разгрузки или продажа
  предметов из списка по ценам рынка Б; «туда и обратно» — рейсы по кругу. Маршрут — по
  выходам зон из справочника игры, путь внутри зоны — в обход построек и воды по схеме зоны.
- **Данжи по кругу из города** — из города в ближайшие зоны допустимой опасности: бегает
  по зоне (по схеме — только по проходимому) и ищет на радаре вход в данж нужного вида
  (по умолчанию зелёные, соло); у портала игроки — не заходит. В данже — этаж за этажом:
  бой (клик по мобу и умения надетых вещей), добыча и сундуки («Взять всё»), разведка,
  выход на следующий этаж; босс, финальный сундук и добыча вокруг — данж пройден. Игроки
  рядом — уход от контакта (в данже — выход тем же путём и поиск другого). Затем выход
  тем же путём, дорога к сундуку в городе, «Положить всё» — и снова. Коды событий
  порталов (`NewRandomDungeonExit`, `NewExit`) — из `events.go`, уточняются `update-opcodes`.
- **Пройти этот данж** — то же внутри данжа, где стоит персонаж.
- **Быстрый выход** из данжа клавишей (в игре — A): переносит к входному порталу. У выхода
  есть задержка, урон её сбивает — бот сначала добивает мобов рядом, следит за ударами и
  повторяет; не получилось — выходит пешком по этажам.
- **Прогулка** — просто ходить по округе.

**Закодированные позиции игроков.** На части серверов координаты игроков приходят не
числами, а 8 байтами с XOR-ключом, который меняется каждые 10 секунд и не передаётся.
Радар подбирает ключ сам: игроки должны быть рядом с вами и двигаться не быстрее своей
(открытой) скорости, а пути — продолжать пути прошлого интервала; после конца интервала
ключ перепроверяется. Игроки появляются через секунду-две после входа в зону, точность —
доли метра (подробности — `albion_trader/radar_crypt.py`).

**Бой и угрозы:**

- **Билд из экипировки** (включён по умолчанию): бот видит, что надето на персонаже
  (событие смены экипировки — достаточно снять и надеть любой предмет), и по справочнику
  игры (`spells.json` из ao-bin-dumps, скачивается вместе с остальными справочниками)
  раскладывает умения по клавишам: оружие — Q/W/E, броня — R, шлем — D, обувь — F, зелье
  и еда — свои клавиши. Лечение жмётся при здоровье ниже 60 %, щиты и усиления брони и
  шлема — ниже 75 %, контроль и урон — по готовности (сначала долгие), рывки в бою не
  жмутся, еда — перед каждым данжем (не чаще раза в N минут), зелье — с перезарядкой из
  справочника. Умения с целью бот наводит на моба (курсор на него перед нажатием) — в
  игре должно быть включено быстрое применение умений.
- **Перезарядки уточняются в бою**: какое умение выбрано в слоте, игра не сообщает, а
  умение, которое ещё не готово, не отправляет запрос — бот засекает, сработало ли
  нажатие, и сужает границы перезарядки (умения брони, усилители и т. п. учтены сами).
  Изученные значения сохраняются для персонажа и предмета и видны во вкладке «Боты».
- **Свой профиль умений** (необязательно): `клавиша:перезарядка@условия` в порядке
  приоритета — `hp<50`, `hp>80`, `boss`, `cast=1.5` (не двигаться), `self` (без цели),
  `open` (первым), `aim` (навести на цель). Например `q:3 w:10@open e:20@boss 2:30@hp<40@self`.
  Строки заменяют автоматические для своих клавиш; без билда и без строк — Q/W/E.
- Не брать групп больше N, отдыхать между группами при низком здоровье, пропускать мобов
  выше тира и элитных, отступать для дальнего боя; бьют — сначала ответить.
- **Угрозы**: друзья не в счёт; враждебный флаг, приближение, сила снаряжения и группа
  повышают опасность. Осторожно — отойти; опасно — зелье побега, маунт, бегом прочь
  (в данже — выход). При перевозке игроки у выхода — объезд через другой выход.
- **Сумка**: перегруз и «сумка полна после N предметов» (события `OverloadModeUpdate`,
  `InventoryPutItem`) — бот несёт добычу домой и возвращается; ремонт и докупка —
  макросами каждые N данжей.
- **Калибровка** — 6 кликов: учитывается перспектива камеры, клики точнее у краёв экрана.

**Сбор и рынок:** если рядом пусто, сборщик идёт туда, где ресурсы бывают (тепловая
карта радара), не раньше времени восстановления; предпочитает узлы в скоплениях. Рынок не
дублирует ваш лучший заказ (видно из трафика), может переставить перебитый, следит за
бюджетом покупок.

**Расписание, профили, статистика:** задача «По расписанию» — окна времени по дням
(`пн-пт 08:00-12:00 gather`, `* 18:00-23:30 dungeon_run Hero`), с переключением на окно
нужного персонажа. Профили сохраняют и загружают наборы настроек. Статистика: серебро и
слава в час, время на данж, гибели; история последних запусков. **Чек-лист** перед запуском
показывает, чего не хватает (места, точки, макросы, умения), и не даёт запустить задачу,
пока обязательного нет.

**Надёжность:**

- **Сторож**: нет прогресса (позиция, зона, добыча, этажи) дольше заданного — бот пробует
  выбраться (быстрый выход в данже, шаги в стороны), потом останавливается. Отдых и паузы
  рынка зависанием не считаются.
- **Оповещения** — правило «Бот» на вкладке «Оповещения» (Windows, Telegram, Discord):
  остановка с причиной, гибель персонажа, игроки рядом, пройденный данж.
- **На радаре** видно, что делает бот: цель, путь по схеме зоны, разведанные места.
- **Запись сессий** («записывать сессии»): трафик окна игры и действия бота в
  `data/bot_sessions/`; `python -m albion_trader bot-session` — сводка по последней записи:
  зоны, запросы и события игры (в том числе неизвестные коды — кандидаты для
  `data/opcodes.json`), клики и журнал. Запись можно прислать разработчику — по ней
  ошибка воспроизводится в тестах.

**Автоопределение точек интерфейса** (вкладка «Боты» → «Точки интерфейса игры»):

- **по надписям**: откройте окно в игре (рынок, окно заказа, добычу, сундук) и нажмите
  «Снимок и распознавание» — бот снимет окно игры и распознает текст встроенным OCR
  Windows 10/11 (нужен установленный русский или английский язык Windows), найдёт кнопки и
  поля по подписям («Продать», «Заказ на продажу», «Цена», «Взять всё», «Положить всё»…) с
  допуском на ошибки распознавания;
- **пробными кликами** — для торговца и сундука (у них нет надписи): встаньте вплотную, бот
  кликает по кругу рядом с персонажем и по трафику узнаёт клик, после которого игра
  отправила не движение, а другой запрос (открылось окно);
- найденное видно на снимке: «Применить найденное» или выбрать точку и кликнуть по снимку.
  Снимок доступен только на этом компьютере.

**Свои макросы** — строки `click 0.52 0.31` / `click @search` / `type {name}` / `key enter` /
`wait 800` / `expect 3000`; клики можно записать («● Запись кликов»), готовые шаблоны —
в списке «шаблон». Ввод «без переключения окна» (сообщения окну) не отнимает мышь, но не
все клиенты его принимают — проверьте «Пробным кликом».

**Проверка:** `check_bots.bat` (или `AlbionTrader.exe check-bots --focus`) — автотесты бота,
функции Windows и права, окна игры и их UDP-порты, трафик, калибровка, места, точки
интерфейса, ошибки в макросах и переключение на окно игры. Отчёт — `data/bots_check.txt`,
настройки — `data/bots.json`.

## Самопроверка на ваших данных

Команда прогоняет все вкладки инструментов на вашей базе и пишет отчёт
`data/check_report.txt` (OK / WARN / FAIL по каждой проверке): сверку сумм в
цепочке производства и билдах, разбор событий игры (слава, серебро, сундуки,
зоны), распознавание данжей и Дорог Авалона, прогнозы Доски судьбы, учёт
серебра, а также ответы API работающей программы. Работает на **копии** базы —
данные не меняются; имён персонажей, гильдий и игроков в отчёте нет.

- из исходников: `check.bat` (или `py -m albion_trader --data-dir data check`);
- из .exe: `AlbionTrader.exe check` — отчёт откроется в Блокноте.

Лучше запускать, когда Albion Trader уже работает и вы немного поиграли
(рынок, мобы, данж, смена зон) — тогда проверится и сборщик.

## Параметры

```
python -m albion_trader [--data-dir DIR] serve [--host 127.0.0.1] [--port 8484] [--game-port 5056]
                                         [--token TOKEN|auto] [--retention-hours 72]
                                         [--no-capture] [--record FILE.pcap]
                                         [--password PASSWORD] [--tray] [--open-browser] [--window]
                                         [--fetch-reference] [--log-file] [-v]
python -m albion_trader replay FILE.pcap
python -m albion_trader update-items
python -m albion_trader update-opcodes
python -m albion_trader update-maps [ZONE ...] [--all]
python -m albion_trader cleanup [--retention-hours 72]
python -m albion_trader check [--url http://127.0.0.1:8484] [--out FILE]
python -m albion_trader check-radar [--url URL] [--out FILE] [--window] [--no-browser]
python -m albion_trader check-bots [--url URL] [--out FILE] [--focus]
python -m albion_trader bot-session [ПАПКА]
```

- `--data-dir` (или `ALBION_TRADER_DATA`) — где лежат база и справочники.
- `--game-port` (или `ALBION_TRADER_GAME_PORTS=5055,5056`) — UDP-порт игрового
  сервера, трафик которого читает сборщик. По умолчанию 5056 (официальные серверы);
  для своего сервера укажите его порт (можно несколько раз).
- `--host 0.0.0.0` открывает доступ из сети (например, с телефона дома) и
  работает только вместе с `--password` (или `ALBION_TRADER_PASSWORD`): браузер
  спросит пароль, запросы с самого компьютера пароль не требуют. Приём данных
  от внешнего клиента защищается отдельно — `--token`.
- `--retention-hours` — через сколько часов удалять заказы, которые больше не видели.
- `--log-file` — писать лог в `albion_trader.log` в папке данных (с ротацией 5 МБ × 3).
- Без `--password` сервер отвечает только на запросы, адресованные `127.0.0.1` /
  `localhost` (защита от DNS rebinding: чужой сайт не сможет прочитать ваши данные
  через браузер).

## Разработка

```sh
python -m unittest discover -s tests -v
```

Структура:

- `albion_trader/capture/` — встроенный сборщик: захват пакетов (`sniffer.py`),
  разбор Photon (`photon.py`, порт из albiondata-client, MIT) и операций игры (`albion.py`);
- `albion_trader/server.py` — приём `POST /<топик>` от внешнего клиента (`marketorders.ingest`,
  `markethistories.ingest`, `goldprices.ingest`), REST API и статика;
- `albion_trader/db.py` — схема SQLite, разбор пакетов, очистка;
- `albion_trader/deals.py` — расчёт сделок и таблицы быстрой продажи;
- `albion_trader/locations.py` — ID локаций → рынки;
- `albion_trader/items.py` — названия предметов;
- `albion_trader/gamedata.py` — рецепты, зачарование, дневники, фермерство, зоны;
- `albion_trader/production.py` — калькуляторы производства;
- `albion_trader/alerts.py`, `notify.py` — правила оповещений и отправка в Telegram/Discord;
- `albion_trader/mytrades.py`, `activity.py`, `world.py` — мои сделки, сессия/лут/персонаж, события мира;
- `albion_trader/chain.py`, `builds.py`, `killboard.py`, `destiny.py`, `avalon.py`, `dungeons.py`,
  `economy.py` — инструменты: цепочка производства, билды, мета, Доска судьбы, Дороги Авалона,
  данжи, учёт славы и серебра;
- `albion_trader/window.py`, `static/companion.html`, `static/js/tools.js` — окно-компаньон и вкладки инструментов;
- `albion_trader/tray.py`, `launcher.py` — значок в трее, автозапуск, точка входа .exe;
- `albion_trader/static/` — веб-интерфейс.
